# AWS demo: provisioning script and what was verified

Companion to [`deploy-vm.md`](deploy-vm.md) (issue #236). That guide describes the single-VM stack;
this page covers the script that creates the AWS host for it and the findings from the first real
deployment (issue #238, 2026-11-04). The admin frontend runs on Vercel, the backend on one EC2
instance that is powered off when the demo is not in use.

## What the script creates

`scripts/aws-demo/aws_demo.py` (`plan`, `up`, `start`, `stop`, `status`, `destroy`) is idempotent and
tags everything `Project=aegisnotify-demo`. `up` creates, in `us-east-2`:

| Resource | Notes |
| --- | --- |
| Instance `m7i-flex.large` | Ubuntu 24.04, 8 GiB, 30 GiB encrypted gp3, IMDSv2 required |
| Security group | Inbound 80 and 443 only. No SSH; administer through SSM Session Manager |
| Elastic IP | Stable `sslip.io` hostnames that survive stop/start |
| IAM | An EC2 role with `AmazonSSMManagedInstanceCore` and a scheduler role limited to stopping tagged instances |
| Idle alarm | Stops the instance when average CPU stays below 10 % for one hour |
| Nightly stop | EventBridge Scheduler, 04:00 UTC every day, as a backstop |

First boot installs Docker, adds 2 GiB of swap, clones the repository and runs
`scripts/deploy init` and `AEGIS_IMAGES=ghcr scripts/deploy up` from #236. Secrets are generated by
`scripts/deploy init` into `/opt/aegisnotify/.env.prod` (mode 600) on the instance and are never
printed by the script. The bootstrap log is `/var/log/aegis-bootstrap.log`; it contains the demo
login, so it is also mode 600.

The script runs locally through boto3, or inside the AWS MCP `run_script` sandbox, which has no
`class` support: the code is plain module-level functions for that reason.

```bash
python scripts/aws-demo/aws_demo.py plan
python scripts/aws-demo/aws_demo.py up --frontend-origin https://<project>.vercel.app --acme-email <you>
python scripts/aws-demo/aws_demo.py stop       # stops compute billing
python scripts/aws-demo/aws_demo.py start
python scripts/aws-demo/aws_demo.py destroy --yes
```

`--frontend-origin` must be the final production origin before the first `up`: Keycloak imports the
realm once, so the redirect URIs cannot be changed by re-running it.

## Findings from the first deployment

- **Only `us-east-2` allows EC2.** The account sits in an AWS Organization whose service control
  policy denies EC2 and load balancer calls elsewhere (an explicit deny that IAM permissions cannot
  override). Check your own account before changing `REGION`.
- **Free-plan accounts can only launch eligible instance types.** `t3.large` was rejected with
  "not eligible for Free Tier". `m7i-flex.large` (2 vCPU, 8 GiB) is eligible and is the size
  `docker-compose.prod.yml` is written for. Run `describe-instance-types` with the filter
  `free-tier-eligible=true` to see your list. `m7i-flex` is not burstable, so no credit
  specification is passed.
- **Building images on the instance fails.** Maven Central was unreachable from the instance
  (`Could not transfer artifact ... from/to central`), the same failure seen from other cloud
  environments. `docker-compose.prod.images.yml` plus `AEGIS_IMAGES=ghcr` makes `scripts/deploy`
  pull the images CI publishes to GHCR instead (about one minute instead of 15 to 30).
  `AEGIS_VERSION` selects the tag; `0.18.1-SNAPSHOT` follows the latest build of `main`.
- **Elastic IP association races the launch.** The association is retried while the instance is
  `pending`.

## Verified on the real instance

- All 12 containers healthy within about four minutes of starting the pull; 3.2 GiB of 7.8 GiB used,
  no swap used.
- `https://auth.<host>/realms/aegis/.well-known/openid-configuration` and
  `https://api.<host>/actuator/health` return 200 with valid certificates; the issuer is the public
  `auth` hostname.
- `/admin` and `/realms/master` on the auth host return 404; the API returns 401 without a token.
- CORS: a preflight from the Vercel origin is allowed; any other origin gets 403.
- The Keycloak client `aegis-admin-frontend` has the Vercel origin as redirect URI.
- The production Vercel deployment serves `/config.json` pointing at the two hostnames.

## Not verified yet

- A real browser login and a notification submitted from the UI.
- That the idle alarm and the nightly stop actually stop the instance. CPU was about 10 % shortly
  after startup; check the idle level and adjust `IDLE_CPU_PERCENT` if it never falls below it.
- A stop and start cycle, and `destroy` against real resources (only run against a simulator).
- Preview deployments on Vercel keep Vercel Authentication; only the production URL is public.

## Cost

Estimates, from memory of public prices for `us-east-2`; confirm in the AWS Pricing Calculator.

| State | Approximate cost |
| --- | --- |
| Running | 0.10 USD per hour for the instance |
| Stopped | About 5 USD per month for the disk and the Elastic IP |
| Left running by mistake | About 70 USD per month |

An AWS Budget (`aegis-demo-credits`, 100 USD per month, alerts at 20, 50 and 80 USD) was created
separately and is not removed by `destroy`.
